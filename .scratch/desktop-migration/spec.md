# Spec: nightmare-mobile 跨平台迁移（Windows / Linux / macOS）

Status: ready-for-agent
Type: spec

> 领域术语见根 `GLOSSARY.md`（Nightmare Desktop、无头引擎、桌面补丁集、复制式复用、纵向切片）；决策依据见 `docs/adr/0001`–`0006`。工单见 `issues/01–25`。测试接缝沿用此前已确认的两条（CLI 端到端、Gradle 测试源集），不新增接缝。

## Problem Statement

项目的 AI 图像/视频生成能力目前只能运行在骁龙手机上：推理依赖高通 NPU，UI 依赖 Android，用户离开手机就无法使用自己的模型与工作流；维护者也没有一个能让 AI coding agent 自主完成“改代码 → 构建 → 测试 → 冒烟”闭环的桌面开发环境。

此外，Phase 1 原工单把 CLI 参数、补丁应用、外部权重下载、真实第三方客户端认证混在同一张工单里，且工单状态没有随代码合并及时更新，导致 agent 无法可靠判断哪些工作已完成、当前可以抓取哪张工单。本机性能也有限，原 DiT 三模型目标及其附属功能不应阻塞主线交付。

## Solution

建立 **Nightmare Desktop**：一个与 Android 版完全解耦的独立桌面工程，分三阶段交付——Phase 0 工程准备（可复现构建 + 测试基线 + agent 导航文档）、Phase 1 无头引擎（CLI 先行，后接 A1111 兼容本地 HTTP API）、Phase 2 GUI（Compose Multiplatform）。推理走 CPU + Vulkan（Windows/Linux）/ Metal（macOS），放弃 NPU；引擎源码以 vendor 方式自持，复用 Android 版代码采用复制式复用。

工单图重排为 01–25：原 15 拆为 18–23，原 17 的 Android API 层与真实客户端认证拆为 24/25。18–23 标记为可放弃，可关闭为 `wontfix` 且不阻塞 Phase 1 关闭。跟踪器采用 `resolved` 作为关闭态，并在关闭时勾选验收项、附提交证据。

## User Stories

1. 作为桌面用户，我想在 Windows/Linux/macOS 上用本地硬件生成图像，所以不需要云端服务或骁龙手机。
2. 作为桌面用户，我想用一条 CLI 命令完成文本生成图像（txt2img），所以可以把生成嵌进脚本与自动化。
3. 作为桌面用户，我想在 CLI 中指定尺寸、步数、采样器、调度器、CFG、seed 与负提示，所以能精确控制生成过程。
4. 作为桌面用户，我想用固定 seed 批量生成，所以能从任一产物的元数据复现整批结果。
5. 作为桌面用户，我想在 stdout 看到每张图的进度行和引擎日志，所以长时间 CPU 运行时能确认任务仍在推进。
6. 作为桌面用户，我想用 CLI 完成图像到图像（img2img），所以能对现有图片做改写与变化。
7. 作为桌面用户，我想用 CLI 列出本地模型目录中的单文件 checkpoint，所以能直接选择自己下载的模型。
8. 作为桌面用户，我想让 `--model` 在启动引擎前检查文件头和格式，所以半个损坏的下载不会浪费几分钟推理时间。
9. 作为桌面用户，我想加载自己的 `.safetensors` 微调模型而无需转换，所以即插即用地使用 CivitAI 权重。
10. 作为桌面用户，我想获得 SDXL 支持，所以能用更大的分辨率生成图像。
11. 作为桌面用户，我想使用 SD 原生 LoRA，所以能给生成叠加风格或角色控制。
12. 作为桌面用户，我想获得本地 A1111 兼容 HTTP API，所以能让其他桌面软件把本机当作生成后端。
13. 作为桌面用户，我想该服务默认关闭且只绑定本机回环，所以不会被局域网访问或意外暴露。
14. 作为桌面用户，我想在 Phase 2 获得节点图 GUI，所以能以可视方式搭建与复用生成流程。
15. 作为桌面用户，我想在无 NPU 的普通电脑上获得可用速度，所以不必购置特定硬件。
16. 作为桌面用户，我想每条失败路径都有明确报错和非零退出码，所以脚本不会把失败误判为成功。
17. 作为 AI coding agent，我想在 Linux 上一条命令完成桌面工程构建与测试，所以能自主验证每次改动。
18. 作为 AI coding agent，我想一条命令跑全部测试并得到明确通过/失败结果，所以能自检不引入回归。
19. 作为 AI coding agent，我想通过 SD1.5 CLI 冒烟出一张 PNG 做端到端验证，所以能确认“改引擎 → 编译 → 冒烟”闭环成立。
20. 作为 AI coding agent，我想用假引擎和合成模型文件跑 CLI 测试，所以没有权重缓存时也能验证参数、进度、错误码与产物结构。
21. 作为 AI coding agent，我想桌面工程内有导航文档说明架构、构建/测试/冒烟命令与禁区，所以不需要每次向人询问上下文。
22. 作为 AI coding agent，我想在本地构建引擎源码而不依赖外部 CI 产物，所以能调试引擎层问题。
23. 作为 AI coding agent，我想复制的源文件有来源追踪，所以能判断一段逻辑的原始语义。
24. 作为 AI coding agent，我想从工单的 `Blocked by` 关系直接算出当前前沿，所以能并发工作而不互相踩踏。
25. 作为 AI coding agent，我想每条验证命令都有超时和日志，所以失败的验证能留下证据而不是挂死会话。
26. 作为维护者，我想桌面版与 Android 版构建、依赖完全解耦，所以一边的改动不会破坏另一边。
27. 作为维护者，我想引擎版本以精确 SHA 固化并记录来源，所以任何构建都可复现、可追溯。
28. 作为维护者，我想全部引擎补丁有一份归属清单和覆盖测试，所以补丁资产不会随人员变动而失传。
29. 作为维护者，我想复制的代码有追踪文档且无自动同步义务，所以两个版本可以独立演进。
30. 作为维护者，我想 Linux CI 在桌面工程变更时自动构建并测试，所以回归在合并前暴露。
31. 作为维护者，我想 NPU/QNN 相关代码留在移动版不动，所以移动版行为零风险。
32. 作为维护者，我想 Phase 0 有客观验收标准，所以准备工作的完成与否可以判定。
33. 作为维护者，我想工单关闭状态带提交证据，所以进度查询不依赖口头确认。
34. 作为维护者，我想本机跑不动的模型目标标为可放弃，所以硬件限制不会变成交付阻塞。

## Implementation Decisions

- **工程形态**：Nightmare Desktop 位于同一仓库顶层的独立 Gradle 构建，锁定依赖版本，与 Android 工程互不引用（ADR-0003）。职责区划分为 CLI 入口、平台无关核心逻辑、vendor 引擎与桌面专属文档。
- **复用策略**：复制式复用——从 Android 工程单向复制源文件，允许就地修改，两版各自演进，无同步机制；每个复制文件在追踪文档中记录来源，桌面自写文件明确标注为非复制（ADR-0001）。
- **推理后端**：CPU + Vulkan（Windows/Linux）/ Metal（macOS），放弃 NPU；Hexagon/QNN 专属代码不进桌面构建（ADR-0002）。
- **引擎管理**：以 vendor 方式自持引擎源码，基线为 happyyzy fork（模型支持补丁的代码上下文），编译期关闭 Hexagon 后端；本地脚本或桌面 CI 自建，不走 release asset 下载（ADR-0004/0005）。三个上游版本以精确 SHA 固化。
- **补丁策略**：桌面补丁集从移动版补丁库中挑选平台无关部分并逐个登记归属；Hexagon/NPU 专属与移动 GPU 专属明确排除；应用方式沿用“按后缀路由 + 应用前后 diff 哈希比对防静默跳过”。
- **无头接口**：先交付可日常使用的 txt2img，再交付 img2img；命令输出采用退出码 + stdout/stderr 契约。进度输出包含 CLI 自身的进度行与引擎转发日志，二者都进入 stdout 并逐条 flush；错误路径非零退出并说明原因。
- **产物元数据**：CLI 为生成的 PNG 写入 A1111 风格参数元数据，记录提示词、负提示、尺寸、步数、采样器、调度器、CFG、seed 与模型名，使批量产物可复现。
- **模型导入**：首个可交付范围是单文件 safetensors 校验与本地模型库列表；GGUF 多文件加载作为可放弃的独立纵向切片，不与单文件加载混在一张工单。
- **HTTP 接口**：先暴露引擎已有的 A1111 兼容服务，默认关闭、开启时只绑定本机回环；Android API 层移植、真实第三方客户端认证各自独立成单。
- **工单图**：Phase 0 为 01–10；Phase 1 主线为 11–14、16–17、24–25；原 15 拆为 18–23。18–23 为可放弃工单，硬件或权重不可得时可关闭为 `wontfix`，且不作为主线工单的前置。
- **跟踪器约定**：关闭态为 `Status: resolved`，勾选验收项并在 Comments 附提交/验证证据；`Optional: yes` 表示可放弃且不阻塞交付。
- **验收分级**：自动命令（假引擎、合成文件、本地 HTTP 请求、清单覆盖测试）是关闭工单的硬条件；真实权重端到端生成在缓存存在时运行并记录结果，不作为 agent 关闭工单的硬前置。
- **GUI（Phase 2）**：Compose Multiplatform，复用节点图纯几何层，自绘渲染层按桌面重写（ADR-0006）。

## Testing Decisions

- **什么算好测试**：只测外部行为——给定输入得到什么输出、退出码、stdout/stderr 和文件，不测内部函数调用或数据结构布局。
- **接缝 1 —— CLI 端到端（最高接缝）**：以假引擎和合成模型文件覆盖参数传递、进度输出、错误退出与产物 PNG；真实缓存权重下的 SD1.5 冒烟作为同一接缝的真实验证，而非新接缝。
- **接缝 2 —— Gradle 测试源集**：平台无关的 JVM 逻辑沿用复制前已有的 JUnit 风格测试；复制代码和桌面自写逻辑都在此源集验证，复制测试是迁移回归基线，就地修改不得使其转红。
- **引擎构建不设测试接缝**：以构建脚本退出码与产物存在性验证，归入引擎工单验收。
- **进度输出断言**：批量运行断言每个产物各有一条包含序号、seed 与目标路径的 stdout 行，并断言引擎自身输出仍被转发到同一流。
- **img2img 断言**：固定 seed 下断言强度 0 的输出与原图一致、强度 1 与原图的像素差异超过写入测试的阈值；不使用人工看图判断“合理渐变”。
- **HTTP 接口断言**：默认关闭；开启后仅绑定回环地址，用本地 HTTP 请求断言端点响应与 PNG 产物。真实 A1111 客户端兼容性单独认证，不以 curl 契约测试冒充完整兼容。
- **补丁清单断言**：清单覆盖补丁库每个文件、每行唯一判定、无幽灵行；应用记录逐个登记成功/跳过及原因。
- **有界验证**：所有构建、测试、冒烟命令带超时并保存日志；事件驱动测试必须有内部超时，避免缺事件时挂死。

## Out of Scope

- 视频模型（Wan 2.2、MiniMax H3）与运动迁移——Phase 2+ 单独评估。
- NPU/QNN 路径的任何桌面适配；移动版任何功能或代码改动。
- 与 Android 版的自动同步机制或共享模块。
- Windows/macOS 的端到端冒烟（各平台到达时独立做；当前阶段只要求可编译）。
- 干净上游基线的引擎化重构——fork 死代码清理将来单独评估。
- `fused`/`graph-cut` 补丁的实际应用——先做定性，且定性工单可放弃。
- GUI（Phase 2）的具体交互设计。
- 本机性能无法承载的 DiT 三模型端到端生成不作为交付阻塞；相关工单可关闭为 `wontfix`。
