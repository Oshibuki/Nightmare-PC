## Problem Statement

桌面对话出图模式已交付：用户用自然语言让 AI 经既有工具命令面改同一份工作流并出图。但迭代成本高——想验证一处 provider/提示词改动，用户只能把上一句重新粘贴一遍；而原样重发同一句又不可靠，因为工作流已被上一轮改过、agent 的对话历史还累积着，同样的输入未必得到同样的结果。

与此同时，桌面 CLI 的图生图（Img2Img）子命令早已完整（给定初始图与 strength、按描述改写），但桌面工作流与运行器只会投影文生图，节点注册表里也没有图片输入节点，用户无法在对话里说「用这张图按描述重画」让 AI 改工作流出图。

如果直接开工，agent 会在实现中反复替用户做决定：重发放哪、放什么、怎么保证可复现；图生图本轮做哪几种、图片从哪来、在工作流里怎么表示、强度谁定、怎么验收。因此先把决策面走完，再产出一份可直接拆成实施工单的规格。

## Solution

在对话模式的输入框旁加一个**单一「重发上一句」按钮**：点击后把上一条已发出的用户消息当作新消息再发、起新回合；重放前先复位工作流并用干净的 agent 上下文，保证同一句反复得到同一实验；UI 对话气泡照常追加保留，与「失败/取消后重试保留上下文」是有意区分的两条路径。

同时开辟**图生图第一条纵向切片**：用户给一张本地图路径与一句描述，AI 经既有工具面在工作流里新增一个最小图片输入节点（携带 path/strength、连到 sampler），运行器按节点是否存在把工作流投影成 img2img 子命令并带上 `--init-img`/`--strength`，假 CLI 出图、产物进结果面板。验收在 Linux 用一条 `verify-gui.sh` 命令闭环；Windows/macOS 仅要求 GUI 模块编译通过。

## User Stories

1. 作为桌面用户，我想在输入框旁点一个「重发上一句」按钮，以便改了 provider 或提示词后用同一句马上重验，不用重新粘贴。
2. 作为桌面用户，我想让「重发上一句」每次都从干净的工作流与 agent 上下文开始，以便同一句反复跑出同一结果，让我的改动真正可比。
3. 作为桌面用户，我想重发时旧的气泡和已生成的图都保留、只追加新的一轮，以便对照前后两次结果。
4. 作为桌面用户，我想在生成运行中这个按钮被禁用并提示「运行中」，以便不会意外发起第二条并发请求。
5. 作为桌面用户，我想在 AI 追问等待时点这个按钮就等于发送新指令（先放行追问再起新回合），以便程序不会卡在追问上。
6. 作为桌面用户，我想在按钮的提示里看到将被重发的那句文本，以便点之前确认没有发错内容。
7. 作为桌面用户，我想在对话里说「用这张图按这句描述重画」并给出本地图片路径，让 AI 搭出图生图工作流并出图。
8. 作为桌面用户，我想让 AI 把初始图当作工作流里的一个节点、而不是一次性的运行参数，以便这张图是我能看见、能被同一份工作流复用的输入。
9. 作为桌面用户，我想让重绘强度由 AI 按我的描述设置（默认 0.75），以便我不必先学参数就能得到合理的重画效果。
10. 作为桌面用户，我想让图生图产出的图进入和文生图相同的结果面板，以便一处就能看到所有产物。
11. 作为桌面用户，我想在文生图工作流里不出现图片节点时一切照旧，以便这次改动不破坏我已有的流程。
12. 作为维护者，我想用假 CLI 在 Linux 上一条命令验证图生图投影带了正确参数、产物进了面板，以便无真实模型也能验收。
13. 作为维护者，我想让图生图验收复用既有验收脚本并新增独立步骤与日志，以便继续维持单一验收入口。
14. 作为维护者，我想让「重试」与「图生图」在术语表里有明确定义、与「参考图输入」区分，以便后续 agent 不再混用这些词。
15. 作为维护者，我想让新增的图片节点与运行器切换有 ADR 记录取舍，以便后来人不会误以为可以走一条独立 CLI 路径。

## Implementation Decisions

- **重试的对象与入口**：重放「上一条已发出的用户消息」，当新消息起新回合；输入框草稿不参与。入口是输入框旁单一「重发上一句」按钮，不在错误/取消/用户气泡上分设（沿用「唯一入口、避免语义散落两处」纪律）。按钮 tooltip 显示上一句被截断的文本。
- **重放的可复现性**：重放前用既有「新建工作流」命令复位工作流，并用干净的 agent 上下文（新建 agent 实例、只带这条消息）起回合；对话气泡照常追加保留。这与「失败/取消后重试保留上下文」是有意区分的两条路径，后者语义不变。
- **重发的并发与追问行为**：运行中按钮禁用并提示「运行中」；追问等待期间点按钮等同发送新指令——先以 CANCEL 放行等待中的追问再起新回合，不新增特例。
- **图生图本轮范围**：只做普通图生图（初始图 + strength/denoise + 描述）；inpaint（局部重绘）与参考图输入（flux_edit / H3 reference 一类）不做。
- **首切片路径**：走对话模式——用户给本地路径与描述，AI 经既有五条工具命令改同一份工作流，运行器投影到既有 CLI 的 img2img 子命令。不新建运行路径，不直接调用引擎入口。
- **图片来源**：用户给出的本地文件路径，经新工具参数传入；从结果面板选图与文件选择器/附件上传不做。
- **工作流表示**：在既有节点注册表（桌面自持纪律，ADR-0007）新增一个最小图片输入节点，携带 `path`/`strength` 参数并连到采样节点；既有工作流 JSON 格式的字符串参数映射可直接承载路径，不改格式版本。运行器按工作流里是否存在该节点决定投影成文生图还是图生图子命令，仍保持单运行、单一 CLI 子进程（ADR-0009）。
- **strength**：由 AI 经工具参数设置，沿用 CLI 默认 0.75、范围 0..1；首切片不做用户侧控件与专门的追问。
- **术语与 ADR**：「重试（Retry）」「图生图（Img2Img）」已入 `GLOSSARY.md`；图片节点 + 运行器切换的取舍已立 ADR-0013（含否决「全局运行参数」与「直调引擎入口」两案）。

## Testing Decisions

- **什么算好测试**：只断言外部可见行为——点了按钮后工作流被复位、agent 上下文是干净的、气泡追加且旧的保留；图生图投影带了什么参数、产出什么图、进了哪个面板；不断言内部实现（线程名、列表内部顺序、粘合层行数）。JVM `org.json` 的键序与 Android 不同，断言按键名比较字段、不做字符串全等。
- **模块与接缝**：全部落在既有接缝上，只扩展不新建——(1) GUI 状态层的 JUnit4 测试（无 Robolectric）验证重发语义与图生图工具链；(2) 假 CLI 端到端断言投影参数与产物；(3) 既有 `verify-gui.sh`（ADR-0011 单一入口）新增独立 img2img 步，用既有 `run_step` 封装、独立日志、硬超时。
- **重放的断言**：同一句重发两次得到一致的工作流与产物；旧气泡与图保留；运行中二次重发被拒且不丢草稿；追问等待时重发先放行再起新回合；重试（失败/取消后）与新「重发上一句」两条路径互不干扰。
- **图生图的断言**：图片节点的 path/strength 经工具参数写入工作流；运行器对含图片节点的工作流投影出 `--init-img`/`--strength`、对不含的工作流仍投影文生图；产物 PNG 进结果面板；strength 默认 0.75、越界被拒。追问双路径与取消语义沿用既有断言，不重复造测试。
- **既有测试先例**：对话模式的状态层测试（回合生命周期、追问回写、provider 接线）、假 CLI 端到端测试、`verify-gui.test.sh` 对步骤日志清单的断言。
- **不测**：真实 provider 调用、真实模型 tool-calling、inpaint、参考图输入、文件选择器、窗口鼠标端到端、Windows/macOS 端到端。

## Out of Scope

- inpaint（局部重绘）与参考图输入（flux_edit / H3 reference 一类）：与图生图语义不同，本轮明确排除。
- 从结果面板选上一张产物图作初始图、文件选择器/附件上传：后续 effort。
- 用户侧重绘强度控件与专门的 Ask 追问：strength 由 AI 经工具参数设置，用户控制看后续反馈。
- 真 provider 端到端冒烟：可选手工，缺环境变量或网络则跳过、不阻塞。
- Windows/macOS 端到端：仅要求 GUI 模块本地编译通过，沿用 ADR-0011。
- 移动版任何改动或自动同步：沿用复制式复用与 ADR-0007。
- 新增运行路径、独立验收脚本、协程、本地配置文件、事件总线：均不引入；单运行入口（ADR-0009）与单一验收脚本（ADR-0011）保持不变。
