# 01: 上一轮输入重试的语义与入口

Type: wayfinder:grilling
Status: resolved

## Question

给对话模式「上一轮输入」加重试按钮，方便快速验证、避免手动粘贴。需要裁决：重放的是哪段文本（已发送的上一条用户消息 vs 当前输入框草稿）？按钮放在哪（单一入口 vs 气泡分设）？重放如何保证可复现（重复 `add_node` 会被拒、`Agent` history 累积会让同一句得到不同结果）？它与「失败/取消后重试保留上下文」是什么关系？

## Answer

- **重放对象**：已发出的上一条用户消息（`ChatItem.User.text`），点按钮把它当作**新的一条消息**再发、起新回合；输入框里没发出的草稿不参与。术语定为「重试（Retry）」，已入 `GLOSSARY.md`。
- **入口**：输入框旁**单一「重发上一句」按钮**，不在错误/取消/用户气泡上分设。理由：工单 12 已确立「唯一入口、避免语义散落两处」；按钮就长在原本要手动粘贴的位置；成功/失败/取消后都可用（「快速验证」最常见的场景恰恰是上一次成功后改了配置）；气泡列表不被稀释。
- **可复现性**：重放前先以既有 `new_workflow` 复位工作流，并用**干净的 agent 上下文**（新 `Agent` 实例，只带这条消息）起回合；UI 对话气泡照常追加保留。否则同样的脚本第二次 `add_node` 因重复 id 被拒、模型看见自己上一轮的工具调用，重放就不是同一实验。
- **与既有重试的关系**：有意区分的两条路径——失败/取消后的重试保留上下文（工单 12 语义不变），「重发上一句」是主动复位的可复现实验。
- **配套行为**：运行中按钮禁用并提示「运行中」；Ask 等待期间等同点发送（先以 CANCEL 放行再起新回合，工单 11/12 既有绕过）；tooltip 显示上一句被截断的文本，避免误发。
