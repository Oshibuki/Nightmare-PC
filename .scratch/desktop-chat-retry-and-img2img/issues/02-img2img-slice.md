# 02: 图生图的交付节奏与首切片形态

Type: wayfinder:grilling
Status: resolved

## Question

用户说「图生图流程也该准备开发了」。裁决两件事：这轮交付到哪一层（先走决策面出地图/规格/工单，还是直接写代码）？第一条纵向切片走哪条路径（对话模式新工具驱动，还是默认/高级模式的图片节点画布）？

## Answer

- **交付节奏**：先走完决策面（wayfinder 地图 → 规格 → 工单），不直接写代码。要动的面很广——新节点类型（ADR-0007 桌面自持）、5 条工具命令、`WorkflowRunner` 写死的 `txt2img`、单运行/关窗清进程（ADR-0009）、验收单一入口（ADR-0011）——直接开工会让 agent 反复替用户做决定。
- **首切片形态**：走**对话模式新工具**：用户说「用这张图按描述重画」→ AI 经工具面改同一份工作流 → 跑出图。沿用「对话驱动既有命令面」的成熟路径与假 CLI 接缝；图片节点/画布操作留到后续切片。
- **理由**：CLI 的 `img2img` 子命令已完整（`--init-img`/`--strength` 等，`Img2Img.kt:48-51`），接缝现成；对话路径能在 Linux 上用假 CLI 闭环，符合 ADR-0011 的验收口径。
