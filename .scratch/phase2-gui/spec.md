## Problem Statement

Phase 0/1 已经把 Nightmare Desktop 做成可复现构建的无头引擎：CLI 能完成 txt2img、img2img、模型导入、SDXL、LoRA 与本地 A1111 兼容服务，但用户仍须在终端敲命令才能生成图片。与此同时，「桌面 GUI 该长什么样」在原规格里只是一句话，连交互外壳、工作流表示、进程生命周期与验收口径都没有决定；如果直接开工，agent 会在实现中反复替用户做决定。

因此需要先把 Phase 2 的决策面走完，再产出一份可直接拆成实施工单的规格：它必须锁定「默认/高级两种模式 + 后置对话模式」的边界，并给出一条能在 Linux 上端到端验证的纵向切片——搭建或载入一条 txt2img 工作流，运行，看到生成的图。

## Solution

在 Nightmare Desktop 中新增独立的 `:gui` JVM 模块，用 Compose Multiplatform 桌面 target 实现两个交互模式：**默认模式**（链芯片 + 参数抽屉，重心在结果）与**高级模式**（自由节点画布 + 节点库 + 属性面板，保留节点图可编辑性）。两种模式操作同一份工作流，切换只换外壳；移动版已有的对话模式本轮不实现，只预留「工作流可由外部工具驱动」的接口。

纵向切片支持新建、载入、保存工作流，运行一次 txt2img 生成，展示逐张进度与引擎日志，并在成功时把 PNG 纳入结果面板。GUI 以子进程驱动 CLI 并持有进程句柄，CLI 保持无状态。验收在 Linux 用一条验收脚本闭环；Windows/macOS 同批只要求 GUI 模块编译通过。

## User Stories

1. 作为桌面用户，我想打开应用就直接看到默认模式与一条可运行的 txt2img 内置工作流，以便无需先配置就能生成第一张图。
2. 作为桌面用户，我想在默认模式看到链芯片与参数抽屉，以便选中一个节点就改它的参数，不必理解画布操作。
3. 作为桌面用户，我想在高级模式看到节点库、连线画布与属性面板，以便按自己的方式搭建和复用生成流程。
4. 作为桌面用户，我想在默认模式与高级模式之间切换时工作流和参数都不丢失，以便从不同视角处理同一条链。
5. 作为桌面用户，我想新建一条空工作流，以便从零搭建自己的生成流程。
6. 作为桌面用户，我想载入本地工作流 JSON，以便复用之前保存的流程。
7. 作为桌面用户，我想把当前工作流保存到指定路径，以便下次打开继续用。
8. 作为桌面用户，我想另存为不同文件，以便保留同一流程的多个版本。
9. 作为桌面用户，我想在载入非法 JSON 时看到具体原因且当前工作流不变，以便不会因为一个坏文件丢失正在编辑的链。
10. 作为桌面用户，我想在载入 `format` 不是 1 的工作流时看到「版本不兼容」，以便不会误打开结构已变的文件。
11. 作为桌面用户，我想工作流只由提示词、采样器与输出三类节点构成就能出图，以便不必先学完整的节点类型表。
12. 作为桌面用户，我想在抽屉或属性面板里填写正向与负向提示词，以便控制生成内容。
13. 作为桌面用户，我想选择采样器与调度器、设置步数、CFG、seed 与尺寸，以便精确控制生成过程。
14. 作为桌面用户，我想用固定 seed 重跑并得到同一张图，以便复现一次满意的结果。
15. 作为桌面用户，我想点「运行」后看到每张图的进度（序号、总数、seed、目标路径），以便知道长时间 CPU 推理仍在推进。
16. 作为桌面用户，我想在同一日志面板看到引擎原始输出，以便进度之外还能看到引擎自身的诊断信息。
17. 作为桌面用户，我想在运行中取消生成，以便不必等一次不满意的推理跑完。
18. 作为桌面用户，我想关闭窗口时结束仍在运行的生成子进程，以便不留后台孤儿进程。
19. 作为桌面用户，我想运行超时后自动结束并给出明确原因，以便卡住的推理不会挂住界面。
20. 作为桌面用户，我想缺模型时看到清晰错误而不是静默失败，以便知道该去导入哪个权重。
21. 作为桌面用户，我想非零退出码、stderr 报错与产物缺失都转成同一条可读错误，以便不必分别理解三种失败格式。
22. 作为桌面用户，我想只有成功生成的 PNG 才进入结果面板，以便失败不会留下看起来像成功的半成品。
23. 作为桌面用户，我想失败后工作流仍可编辑，以便改完参数就能重跑。
24. 作为桌面用户，我想在结果面板看到产物的路径与参数，以便知道哪张图对应哪次设置。
25. 作为桌面用户，我想在自己的普通电脑上生成图片而不依赖骁龙手机或云端服务，以便离线使用自己的模型。
26. 作为桌面用户，我想两种模式共享同一份工作流数据，以便切换视角不产生两份需要同步的链。
27. 作为 AI coding agent，我想一条命令跑完构建、测试、假 runner 端到端与可选真实冒烟，以便一次就能知道改动是否回归。
28. 作为 AI coding agent，我想没有权重缓存时也能完成端到端验证，以便不依赖外部下载就能自检。
29. 作为 AI coding agent，我想有缓存时用真实 SD1.5 冒烟并留下结果，以便确认真引擎路径仍然可用。
30. 作为 AI coding agent，我想假 CLI runner 能复现进度行与四类失败信号，以便进度与失败路径都能自动断言。
31. 作为 AI coding agent，我想每条验证命令都有超时与日志，以便失败能留下证据而不是挂死会话。
32. 作为 AI coding agent，我想从规格与 ADR 直接知道哪些决策已定，以便不重复做设计访谈。
33. 作为 AI coding agent，我想文档说明 GUI 如何定位 CLI 可执行文件，以便不必猜路径。
34. 作为维护者，我想 GUI 模块与 Android 工程完全解耦，以便一边的改动不会破坏另一边。
35. 作为维护者，我想桌面节点类型只含表现语义、不含执行语义，以便移动版的 NPU/视频节点不会漏进桌面。
36. 作为维护者，我想复制的几何与状态代码就地改类型引用但不回写移动版，以便两版各自演进。
37. 作为维护者，我想 Compose 与 Kotlin 版本集中锁定，以便任何机器上的构建都可复现。
38. 作为维护者，我想对话模式后置但工作流能被外部工具驱动，以便将来实现对话模式时不必重做工作流表示。
39. 作为维护者，我想 GUI 不直接使用 A1111 HTTP 作为驱动接缝，以便避免依赖当前并不完整的进度端点。
40. 作为维护者，我想 Windows/macOS 先只要求编译通过，以便不把当前机器无法验证的平台变成交付阻塞。

## Implementation Decisions

- **模块与构建**：新增独立的 `:gui` JVM 模块，保留 `org.jetbrains.kotlin.jvm`，不切换多平台插件；Compose compiler 插件取 Kotlin 同版本，Compose Multiplatform 插件取 1.12.2，Gradle 8.14.4 / JDK 17 沿用现有锁定版本。依赖仓库在集中声明处加入 Google Maven 以解析 `androidx.*` 通用构件，同时保持「模块不得自行声明仓库」的严格模式。加仓库不等于引入 Android 插件或 target。依据 ADR-0006 与工单 01 的结论。
- **交互模式**：默认模式采用「链芯片 + 参数抽屉」布局——顶部横向工作流链、左侧大结果预览、右侧参数抽屉；高级模式采用「节点库 + 自由画布 + 属性面板 + 结果条」布局。两者共享同一份工作流与同一套节点类型，切换只换交互外壳。表单化步骤变体被否决。完整对话模式后置，本轮只要求工作流提供一个等价「由外部工具驱动」的命令面，供将来的对话 effort 继承。依据 ADR-0008 与工单 02 的裁决。
- **图模型与节点类型**：桌面自写最小图模型与最小节点类型——节点类型只含画布所需表现成员（端口、标题、宽度、是否显示结果等），不含执行语义。首批只覆盖提示词、SD 采样器、输出三类节点。从移动版复制几何层与状态层时，就地把类型引用换成桌面定义；不复制执行与迁移逻辑，不改动移动版一行代码；复制带来的 JVM 测试作为回归基线。依据 ADR-0007 与工单 04/08 的结论。
- **工作流持久化**：桌面自写最小 JSON 读写，不复制移动版读写实现（其传递依赖会带入 NPU/视频资产与资源引用）。线格式含根 `format`（固定 1）、`nodes`，以及可选的 `requires` 与 `view`；节点记录 id、类型、参数、输入连线与位置。节点 id 必须是安全文件名，拒绝点、斜杠与控制字符。严格接受 `format=1`；保存采用唯一临时文件 + 原子替换的思路。支持新建、载入、显式保存与另存为，不做自动保存。
- **进度与失败呈现**：GUI 逐行解析 CLI stdout 的进度行形成进度事件（序号/总数/seed/目标路径），同时把引擎原始输出转发到同一日志面板；二者不二选一。非零退出码、stderr、超时、缺模型统一转成运行态失败，错误条显示退出码与首行原因、全量进日志。GUI 侧设可配置超时（默认十分钟），超时结束子进程。依据 ADR-0010。
- **进程边界与运行态**：GUI 以子进程启动 CLI 并持有进程句柄、逐行读取 stdout；不直接调用进程内的纯函数入口，也不扩大 internal 可见性。CLI 每次调用保持无状态，工作流与结果归 GUI 状态。同一时刻只允许一次运行，运行时禁用「运行」；支持取消，关闭窗口也必须结束子进程。只有成功退出才把 PNG 纳入结果面板，失败或取消的临时产物删除。依据 ADR-0009。
- **验收**：Linux 用一条验收脚本串起 GUI 编译校验、全量构建与测试、假 runner 端到端，以及权重缓存存在时的真实 SD1.5 冒烟；每步限超时并留存日志，无头图形运行套虚拟显示。真实权重冒烟可选，不阻塞无缓存环境。Windows/macOS 本轮只要求 GUI 模块本地编译通过，不新建 CI job。依据 ADR-0011。
- **测试接缝**：不新增测试接缝，不引入 UI 测试框架。领域术语统一使用 `GLOSSARY.md` 中的定义。

## Testing Decisions

- **什么算好测试**：只断言外部行为——命令输出、退出码、stdout/stderr、生成的文件，以及 GUI 的运行态与结果列表；不测内部函数调用或数据结构布局。
- **接缝 1 —— CLI 端到端（最高接缝）**：假 CLI runner 加合成工作流 JSON，覆盖新建/载入/保存、进度事件、四类失败（非零退出码、stderr、超时、缺模型）、安全 id 校验、版本不兼容、原子保存与「工作流未变」。真实权重下的 SD1.5 冒烟是同一接缝的真实验证，缓存存在时运行并记录，不作为硬性前置。
- **接缝 2 —— Gradle 测试源集**：复制来的几何与状态代码沿用移动版已有的 JUnit 测试作为迁移回归基线，就地修改不得使其转红；桌面自写的最小图模型、节点类型、JSON 读写与运行态状态机也在该源集验证。
- **进度断言**：每张产物各有一条包含序号、seed 与目标路径的 stdout 行被解析成进度事件，且引擎原始输出仍转发到同一日志面板。
- **失败断言**：失败路径断言运行态为失败、错误条包含可读原因、当前工作流保持不变、结果面板没有半成品产物。
- **有界验证**：所有构建、测试、冒烟与假 runner 命令都带超时并保存日志；事件驱动的测试内部必须有超时，避免缺事件时挂死。

## Out of Scope

- 完整对话模式的实现、LLM provider 配置与密钥管理：本轮只预留外部工具驱动接口，边界见 ADR-0008。
- 表单化步骤交互变体（原型 B）：已在工单 02 否决，不进入任何交互模式。
- A1111 兼容 HTTP 作为 GUI 的驱动接缝，以及其 `progress`/`interrupt`/`options` 端点改造。
- GUI 内只读集成 A1111 HTTP 的模型列表。
- 为 GUI 引入 Compose UI 测试框架这一新接缝。
- 完整对标 Android 节点编辑器；视频模型与 DiT 三模型的端到端生成。
- 移动版任何功能或代码改动，以及与移动版的自动同步机制。
- Windows/macOS 的端到端冒烟与 CI：当前阶段只要求编译通过。
- 工作流的自动保存、多工作流并行运行、进度 HTTP 端点。
