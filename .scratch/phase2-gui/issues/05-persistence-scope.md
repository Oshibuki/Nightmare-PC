# 05: 工作流的保存与载入范围

Type: wayfinder:grilling
Status: resolved
Blocked by: 04

## Question

纵向切片是否必须同时支持「新建一条链」和「载入已有 JSON」，还是只需载入内置配方并允许编辑？

保存/载入的失败路径——非法 JSON、版本不兼容、目标路径不可写——分别怎样向用户呈现，并写进自动化验收断言？

## Answer

**范围**：最小闭环——新建 + 载入 JSON + 保存到本地文件；工作流格式用工单 04 给出的最小线格式（根 `format=1` + `nodes[id,type,params,inputs,x,y]`）。**版本**：只接受 `format=1`，其他值拒绝并报「版本不兼容」，不宽容解析、不自动升级。**术语**：统一为「工作流」，随应用分发的预置项称「内置工作流」；「配方（Recipe）」退居移动版实现类名，已写入 `GLOSSARY.md` 的 _Avoid_。

**保存时机**：显式「保存 / 另存为」菜单，运行前不自动保存。**失败呈现**：非法 JSON（语法错 / 缺字段 / 不安全 id）、版本不兼容、保存失败（路径不可写 / `ATOMIC_MOVE` 失败）三类统一走界面内错误条，显示文件名 + 具体原因；保留当前工作流不变，不弹系统模态框、不自动另存。**验证**：在 Gradle 测试源集里用临时目录 + 合成坏文件（非法语法、`format=2`、非法 id、只读目录）跑假 CLI runner 的端到端用例，断言错误文案与「工作流未变」；沿用既有测试接缝，不引入 UI 测试框架。
