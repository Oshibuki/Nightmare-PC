## Problem Statement

Nightmare Desktop 的 Phase 2 GUI 已经交付默认模式（链芯片 + 参数抽屉）与高级模式（自由节点画布），两者以子进程驱动 CLI 出图。但用户仍须自己搭建工作流、填提示词、点运行；移动版已有的「对话出图」能力——用户用自然语言给 prompt 或修改意见、AI 改写提示词或参考图出图——在桌面侧没有。ADR-0008 已把对话模式裁决为后置 effort，本轮只留了外部工具命令面。

如果直接开工，agent 会在实现中反复替用户做决定：对话模式长什么样、agent 线程怎么跑、Ask 追问怎么回写、密钥与 provider 存在哪、怎么验收。因此需要先把这些决策面走完，再产出一份可直接拆成实施工单的规格：它必须在Linux 上给出一条端到端纵向切片——用户用对话描述想要的画面 → AI 经既有工具命令面改同一份工作流 → 运行 → 在结果面板看到生成的图。

## Solution

在 Nightmare Desktop 的 `:gui` 模块新增第三种交互模式——**对话模式**，与默认/高级模式并列、共享同一份工作流会话。对话模式以单列对话为主体：用户的自然语言与 AI 的回复、工具摘要、产物图、错误、结构化追问（Ask，可点击选项）以气泡呈现，工作流收为顶部面包屑条。桌面适配器复用从移动版逐字节复制的纯 JVM agent 核心（`Agent`/`LlmClient`），重写 Android 耦合的宿主层：后台线程每回合跑一次 `Agent.send()`，通过工具命令面驱动既有工作流，事件经回调 + 主线程切换入 Compose 的对话列表。

移动版的对话模式零改动，桌面复用移动版资产的唯一方式是复制式复用（本规格已落地的两份源文件见工单 03 证据）。验收在 Linux 用一条扩展后的 `verify-gui.sh` 闭环，以假 ChatModel + 假 CLI 跑通全链路；Windows/macOS 同批只要求编译通过。

## User Stories

1. 作为桌面用户，我想在默认/高级模式之外看到一个对话模式入口，以便用自然语言而不是手动搭工作流来出图。
2. 作为桌面用户，我想在对话里描述想要的画面（如「清晨薄雾里的城市，柔和光线」），让 AI 帮我搭出或调整工作流并出图。
3. 作为桌面用户，我想在对话里提出修改意见（如「把 seed 固定成 184203」），让 AI 调整同一份工作流重跑，而不是另起一条。
4. 作为桌面用户，我想看到 AI 的回复、工具调用摘要、错误和生成的图都以气泡呈现，以便在一个地方理解发生了什么。
5. 作为桌面用户，我想点选 AI 的追问选项（如「固定 seed 重跑」/「换随机 seed」）来继续同一轮生成，而不必重新描述整个需求。
6. 作为桌面用户，我想在 AI 追问时改用输入框打字，系统先取消那个追问再处理我的新消息，以免卡住。
7. 作为桌面用户，我想在生成过程中点「取消」，让当前出图在当前工具收尾后停下、已生成的图保留，而不是硬杀或完全没反应。
8. 作为桌面用户，我想在生成运行中继续输入文字，但发送按钮被禁用并提示「运行中」，以免发出第二条并发请求。
9. 作为桌面用户，我想在生成运行中切到默认或高级模式，后台出图继续、结果仍进入同一份工作流，切回来能看到对话历史。
10. 作为桌面用户，我想在对话模式里点开工作流面包屑节点看到一个只读抽屉，以确认 AI 到底改了工作流的哪一处。
11. 作为桌面用户，我想通过对话模式内的设置入口选择 provider、填 base URL 和密钥，以便按自己的账号出图。
12. 作为桌面用户，我想让 provider 与密钥由环境变量持久、弹窗输入只在本次运行生效，以便不在磁盘上留下密钥又能在 CI/无头环境注入。
13. 作为桌面用户，我想保存配置时做一次快速连通性检查，但检查失败仍能保存，以便无网络时也能先配好。
14. 作为桌面用户，我想让 AI 自动挑一个可用模型、也能手动指定，以便开箱即用同时保留选择权。
15. 作为桌面用户，我想在密钥未配置或连不上 provider 时看到明确的错误气泡和「打开设置」按钮，而不是应用崩溃或静默失败。
16. 作为桌面用户，我想让密钥只显示「已配置/未配置」、绝不回显，以便截图和日志都不会泄露它。
17. 作为桌面用户，我想在失败或取消后重试时保留对话历史、追加新气泡，以便保留上下文而不必重述。
18. 作为桌面用户，我想我的对话历史在切换模式时保留、重启应用后清空，以便会话连续又不产生持久化负担。
19. 作为维护者，我想在 Linux 上用一条 `verify-gui.sh` 命令验收对话出图全链路，以便快速确认改动没有破坏主流程。
20. 作为维护者，我想用假 ChatModel + 假 CLI 断言对话→工作流→出图，以便无需真实 provider 密钥或网络就能验收。
21. 作为维护者，我想断言 Ask 的放行与取消两条路径，以便追问不会把后台线程挂死。
22. 作为维护者，我想 Windows/macOS 只要求编译通过、真 provider 冒烟可选，以便不被平台与网络条件阻塞交付。
23. 作为维护者，我想复制的 agent 核心带溯源注释、桌面副本就地维护、不回同步移动版，以便两版各自演进。

## Implementation Decisions

- **模块**：扩展既有 `:gui` 模块（新增对话模式壳、桌面适配器、设置弹窗）；`:core` 增加从移动版复制的纯 JVM agent 核心——`Agent` 与 `LlmClient`（逐字节复制、仅加溯源注释，实测 `:core:compileKotlin` 0 行改动）。不新建模块。移动版零改动。
- **复制边界**：只复制 `Agent`/`LlmClient`。Android 耦合的 `AgentConfig`/`AgentTools`/`AgentSession`/`CanvasHost` 不复制，其职责由桌面适配器重写。复制文件按既有 `copied-files.md` 纪律登记、首行加溯源注释。
- **对话模式形态**：第三种交互模式，与默认/高级共享唯一工作流会话。单列对话为主体；工作流收为顶部面包屑条；面包屑节点可点开只读工作流抽屉（复用既有工作流数据做只读呈现，编辑仍归默认/高级模式）；provider 设置入口为对话区内的齿轮按钮弹窗。
- **agent 核心对接**：桌面适配器实现 `ChatModel`（fun interface，单方法 `complete(messages, tools)`）与 `ToolBox`（`specs`/`call`/`summary`）。工具面只用既有五条命令（新建工作流、添加节点、设置参数、连线、运行）经既有工具接口驱动；约 60 行粘合层把工具名映射到命令、`Ok`/`Rejected` 映射到移动版工具结果形状。对齐移动版全部工具、参考图输入均不在本规格范围。
- **线程与回合**：每个对话回合起一个命名后台线程跑 `Agent.send()`（不引入协程依赖）；同一时刻只允许一个回合。回合＝一次 `send()` 调用。不修改既有运行器的阻塞语义（ADR-0009 单运行/可取消/关窗清进程保持）。
- **事件回传**：构造 `Agent` 时传 emit 回调，把六类事件（User/Assistant/Tool/Picture/Error/Ask）经主线程切换写入 Compose 的可观察列表；Picture 同时按既有监听/快照路径入结果面板。引擎日志事件不进气泡、仍走既有运行日志面板。不新增事件总线、不污染运行态通知链。
- **取消语义**：协作式停止——置取消标志、等当前工具调用收尾、在下一轮首真正停；不发新 LLM 请求；不硬中断线程。取消气泡标「已取消」、保留已产出图与历史。运行中切模式只切外壳、后台继续；关窗沿用既有清进程路径。
- **并发与重试**：运行中发送按钮禁用并提示「运行中」，不排队。失败/取消后允许重试，以新用户消息追加历史、起新回合，不抹掉旧气泡。历史只在内存：切换保留、重启清空。
- **Ask 回写契约（结构化追问）**：桌面适配器复刻移动版语义——后台回合在 Ask 处等 `CompletableFuture`，UI 点选用 `answer(id, option)` 放行，agent 拿选项在**同一回合**继续工具调用；不把 Ask 变成新回合消息。Ask 的 id/question/options/answer 四字段全留内存，用于精确匹配与显示选中项，不进工作流 JSON。用户在 Ask 等待时改用输入框，先以 `CANCEL` 放行再起新回合；切模式不影响等待中的 Ask。取消或关窗时所有等待中的 Ask 以 `CANCEL` 值放行，气泡标「已取消」，不自动选第一个选项、不允许永久挂起。桌面不复制 Android 耦合的 `AgentSession`，但其 ask/answer/stop 语义由适配器等价实现（ADR-0008）。
- **provider 配置与密钥**（ADR-0012）：配置四件——provider（5 家 + 自填 base URL 的 Custom）、base URL、密钥、模型。持久来源只认环境变量（`NIGHTMARE_LLM_PROVIDER`/`_BASE_URL`/`_KEY`/`_MODEL`，沿用既有 `NIGHTMARE_*` 纪律）；设置弹窗输入只存本次进程内存、覆盖环境变量，重启回退环境变量，不写任何配置文件。优先级：内存 > 环境变量 > 内置默认（provider 默认 OPENROUTER，Custom base URL 须注入）。保存时用独立短超时探针（连接 3s/读取 8s）后台做一次连通性检查，失败仍允许保存，不改 agent 核心硬编码的超时；模型由既有选模逻辑自动挑一个可用者作默认，可选「模型」输入框覆盖。无配置/连不上分两类错误文案，错误气泡带「打开设置」按钮、不自动重试。密钥框为密码类型，关闭后界面只显示「已配置/未配置」，不回显、不显示尾四位；密钥只进 `Authorization: Bearer` 头（仅非空白时发送），绝不进工作流 JSON、日志或截图。
- **术语**：「对话回合」「结构化追问」已入 `GLOSSARY.md`；provider/base URL/密钥/模型为通用技术词，不新增领域术语。

## Testing Decisions

- **什么算好测试**：只断言外部可见行为——搭出什么工作流、跑了什么命令、产出什么图、发了什么事件、界面显示什么状态；不断言内部实现细节（如具体线程名、列表内部顺序、粘合层行数）。JVM `org.json` 的 `HashMap` 键序与 Android 不同，断言按键名比较字段、不做字符串全等（工单 01 实测）。
- **模块与接缝**：全部验收落在既有接缝上，只扩展不新建——(1) 扩展 `verify-gui.sh`（ADR-0011 单一入口）在假 runner 步后加 `chat-turn` 步，用既有 `run_step` 封装、独立日志、硬超时；(2) 复用工单 03 已验证的假 ChatModel / 假 ToolBox / 粘合层底座（在丢弃分支 `task/03-fake-chatmodel@496c7e9`，实现时按其笔记落地）；(3) 复用既有监听/快照路径断言结果入面板；(4) JVM 测试源集（JUnit4，无 Robolectric）。
- **断言内容**：假 ChatModel 脚本驱动真实 agent 循环 → 五条工具命令 → 假 CLI → 产物图，断言搭出 `prompt→sampler→output`、seed、Picture 事件、结果入面板；Ask 双路径——点选 `answer(id,option)` 后同回合继续出图、取消/关窗时以 `CANCEL` 放行且线程不挂起且气泡标「已取消」。
- **既有测试先例**：`FakeChatModelWorkflowTest`（工单 03，假 CLI 端到端）、`ToolInterfaceTest`（假 CLI runner，`fakeCliPng` 接缝）、`WorkflowRunnerTest`（取消/单运行）、phase2-gui 工单 14 的结果面板监听测试。复制来的 `AgentTest` 类需裁剪 Robolectric 与 `AgentTools` 用例、修键序断言后方可用于桌面。
- **不测**：真实 provider 调用、真实模型 tool-calling 行为、鉴权/限流、窗口弹窗与鼠标端到端、Windows/macOS 端到端——均不在本轮验收范围。

## Out of Scope

- 对齐移动版 `AgentTools` 全部工具（列模型、保存、LoRA 下载/删除、Civitai 设置等）：本轮只用既有五条命令，留到后期 effort。
- 参考图输入（用户给参考图让 AI 参考出图）：本轮最小闭环不含。
- 对话历史持久化与工作流 JSON 扩展：历史只在内存，`format=1` 不变。
- 真实 provider 调用、账号开通与密钥采购：可选手工冒烟，不阻塞验收。
- 移动版任何改动或自动同步：沿用复制式复用与 ADR-0007。
- Windows/macOS 端到端验收：沿用 ADR-0011，仅要求 GUI 模块本地编译通过，不建 CI job。
- 为 GUI 引入协程、本地配置文件、独立事件总线、三平台 CI 等新接缝。
- 修改既有运行器的阻塞/取消语义（ADR-0009）或 agent 核心的硬编码超时。
