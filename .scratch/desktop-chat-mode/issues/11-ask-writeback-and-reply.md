# 11: 结构化追问（Ask）的放行与回写

**What to build:** 作为桌面用户，我能点选 AI 的追问选项让同一轮出图继续；我改用输入框打字时，那个追问不会把程序卡住——追问的等待与放行是同一回合内的同步握手，不是一条新消息。本工单只提供追问子系统的**放行机制与原语**（点选放行、输入绕过、取消原语），不接 UI 的取消/关窗入口——统一取消入口由 12 编排（避免取消语义散落两处）。

**Blocked by:** 09 — 第三条对话模式与一条对话回合

**Status:** ready-for-agent

- [ ] 追问气泡渲染为可点击选项；点选后 `answer(id, option)` 放行后台等待，agent 拿选项在同一回合继续工具调用，不另起回合
- [ ] 追问的 id/问题/选项/答案四字段全留内存，用于精确匹配与显示选中项；不进工作流 JSON、不落盘
- [ ] 追问等待时用户改用输入框：先以 `CANCEL` 值放行再处理新消息起新回合；切模式不影响等待中的追问（切回仍可点选）
- [ ] **提供取消原语**：暴露一个「以 `CANCEL` 值放行所有等待中追问」的原语供 12 的统一取消/关窗入口调用；不自动选第一个选项、不允许追问永久挂起。本工单**不**自己接 UI 取消按钮或关窗逻辑——那是 12 的职责，避免同一取消入口两处实现
- [ ] 桌面适配器复刻移动版追问语义但不复制其 Android 耦合宿主层；本工单与 10 改 gui 不同区域，可并行开发
