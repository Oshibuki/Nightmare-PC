# 10: provider 设置与密钥注入

**What to build:** 作为桌面用户，我能在对话模式里通过齿轮设置入口配置自己的 provider、base URL 和密钥；这些配置真正喂给 agent 的生产 ChatModel，让我描述的画面能经真实 provider 出图；无密钥或连不上时看到明确错误与「打开设置」出口，密钥在任何界面都不回显——全程不把密钥写到磁盘。

**Blocked by:** 09 — 第三条对话模式与一条对话回合

**Status:** ready-for-agent

- [ ] 设置弹窗提供 provider 选择（五家 + 自填 base URL 的 Custom）、base URL、密钥、可选模型输入；配置由环境变量持久、弹窗输入只在本次进程内存、覆盖环境变量、重启回退，不写任何配置文件
- [ ] 保存时用独立短超时探针在后台做一次连通性检查，失败仍允许保存；不改 agent 核心硬编码超时；模型自动挑一个可用者作默认、可手动覆盖；优先级 内存 > 环境变量 > 默认
- [ ] **生产接线**：provider 配置（provider/base URL/密钥/模型）经环境变量与内存注入到 agent 的 ChatModel，由 `:core` 复制来的 `LlmClient` 承担生产实现；假 ChatModel 仍只留在测试源集。这补上 08「复制 LlmClient」与 09「假 ChatModel 跑通回路」之间的缝隙——否则测试全绿但真实 provider 出图无人负责
- [ ] 无配置/连不上分两类错误文案；错误气泡带「打开设置」按钮、不自动重试、不改变工作流
- [ ] 密钥框为密码类型；关闭后界面只显示「已配置/未配置」，不回显、不显示尾四位；密钥只进 Authorization 头（仅非空白时发送），不进工作流 JSON、日志或截图
- [ ] 本工单与 11 改 gui 不同区域，可并行开发；合并后全量测试通过
